# 技术说明（格式与判断依据）

## 1. 三种数据形态

### 1.1 喵斯兔产出的 .mdm（损坏）
- .mdm = zip，包含 cover.png / demo.ogg / mapN.bms / music.ogg / info.json
- info.json 是 **“清单型”结构**（schema/cid/meta/files），带 UTF-8 BOM，
  且只带了部分 CAM 字段（name/author/bpm/difficulty2/levelDesigner2/charter/levelDesigner）
- 已知问题：BOM；bpm 可能为 "0"；顶层缺 scene/sceneEgg/difficulty1,3,4,5/levelDesigner1,3,4,5/
  hideBmsMode/hideBmsDifficulty/hideBmsMessage/unlockLevel/searchTags/battleUi
- 说明：这里的“清单型”只描述数据模型；喵斯兔是把另一种清单格式错写进了 info.json，**不是 Euterpe 或 Euterpe 模组的问题**（Euterpe 不会生成这种 info.json）。

### 1.2 合法 CustomAlbums info.json（Euterpe 可识别）
```json
{
  "name": "...", "author": "...", "bpm": "172", "scene": "scene_03", "sceneEgg": "none",
  "levelDesigner": "...", "levelDesigner1": "...", "levelDesigner2": "...",
  "levelDesigner3": "...", "levelDesigner4": "...", "levelDesigner5": "...",
  "difficulty1": "0", "difficulty2": "9", "difficulty3": "0",
  "difficulty4": "0", "difficulty5": "0",
  "hideBmsMode": "CLICK", "hideBmsDifficulty": "0", "hideBmsMessage": "",
  "unlockLevel": "0", "searchTags": [], "battleUi": "default"
}
```
- 无 BOM；全部数值/难度为字符串；scene 必须 scene_01..scene_12；
  difficultyN 必须与包内是否存在 mapN.bms 对应（"0" 表示没有）。
- 来源：MDMods/CustomAlbums 的 AlbumInfo.cs（https://github.com/MDMods/CustomAlbums）
  以及社区谱面实测样本。

### 1.3 Euterpe 原生离线谱
- 目录：`Euterpe_Charts/Offline/<谱面名>/`
- 文件：cover.png 或 cover.webp / demo.ogg / mapN.bms / music.ogg / manifest.epk
  （可有 mapN.talk、mapN.json、视频等）
- manifest.epk = MessagePack（不是文本），结构：
```
{ schema:1, cid:null, meta:{ name,name_romanized,author,description,safe_for_streamer,
  bpm,bpm_min,bpm_max,scene,scene_egg,background_video_opacity,search_keywords,
  maps:{ mapN:{rating,charters:[...],predicted_rating:null} },
  hide_mode,hide_rating_override,hide_message,cover_dominant_color,uploader,created_at,updated_at },
  files:{ "<文件名>":{version:1,size:<真实字节数>} } }
```
- 离线谱 files 里不包含 manifest.epk 自身；version=1。

## 2. CAM → Euterpe 的官方迁移映射（已实测验证）
用一份 .mdm 与 Euterpe App 官方迁移后的离线谱逐字节比对（ref.files 尺寸与 .mdm 内文件完全一致）：

| CAM 字段 | 清单型 info.json（喵斯兔写入） |
|---|---|
| name / author | meta.name / meta.author |
| bpm（字符串） | meta.bpm（数字） |
| scene | meta.scene |
| sceneEgg | meta.scene_egg（官方迁移丢弃，置 null） |
| levelDesigner/levelDesignerN | meta.maps.mapN.charters[0] |
| difficultyN | meta.maps.mapN.rating（字符串） |
| hideBmsMode | meta.hide_mode |
| hideBmsDifficulty | meta.hide_rating_override（字符串） |
| hideBmsMessage | meta.hide_message |
| searchTags | meta.search_keywords |
| 包内文件 | meta.files（version=1，size=真实大小） |

## 3. BMS 兜底解析
mapN.bms 文本（可能有 BOM），头部字段：
- `#BPM 160`：bpm 缺失/为 0 时兜底
- `#GENRE scene_03`：scene 非法时兜底
- `#PLAYLEVEL 9`：难度缺失时兜底

## 4. Euterpe 1.1.x 的行为依据

> 运行要求：**Euterpe v1**（新版自制谱系统，实测 1.1.x）。以下为格式/行为依据的整理。
从已安装 Euterpe.Hot.dll（原生核心）内嵌更新日志可读到：
- 旧版 CAM 谱面（.mdm）会在启动时导入「Euterpe 离线」曲包，可以直接游玩；只导入前三个难度，
  没有音乐的谱面会跳过（v0.5.x 加入）
- Custom_Albums 里含 info.json 的旧版 CAM 谱面文件夹也会载入为离线谱面（后续版本）
- 提示可以前往 Euterpe App 批量转换旧版 CAM 谱面（转换会删除原 .mdm）
- 当前版本的解析校验较严格，会拒绝：BOM、非正 BPM、非法 scene、难度槽与包内 bms 不一致等

> 注：Euterpe 后续版本行为可能变化。若某版本不再支持旧版 CAM，建议使用方案 2（原生格式）。

## 5. 数据安全
- 源 .mdm 除 info.json 外的字节不变；改写前备份原 info.json
- 备份目录 `_ChartFixerBackup` 放在游戏目录（Custom_Albums 之外），不会被 Euterpe 当作谱面扫描

## 6. 名词解释（避免误解）

- **清单（manifest）**：一类“描述这个包有什么”的元数据文件，不是 Euterpe 独有概念。
- **清单型 info.json**：顶层是 `schema / cid / meta / files` 的 info.json。本工具报“清单型结构”只是描述它的数据模型，**不是说 Euterpe 有问题**；Euterpe 从来不会生成这种 info.json，喵斯兔在把谱面转成 .mdm 时把同类清单格式错写成了 info.json。
- **manifest.epk**：Euterpe 原生谱面自己的清单文件（二进制 MessagePack），与本工具说的“清单型 info.json”不是同一个东西：前者是 Euterpe 正常格式，后者是喵斯兔写错的 JSON 文本。
- **CAM 结构**：CustomAlbums 的扁平字段格式（`name / author / bpm / scene / difficulty1..5 / levelDesignerN / hideBms* / …`），Euterpe v1 读取旧版 CAM 谱面时使用。
- **BOM**：文件开头的 `EF BB BF` 字节，部分严格 JSON 解析器会因此报错。
- **MessagePack**：一种二进制 JSON 序列化格式，manifest.epk 用它编码。
